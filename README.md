# block_qq 黑名单 / 正则关键词拦截插件

一个 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 插件：前置黑名单与正则关键词拦截，阻断所有插件读取被屏蔽消息，减少 Token 消耗。

## 适用场景

- 屏蔽指定 QQ 用户的消息（例如其他机器人），避免刷屏图片、大量消息造成 Token 浪费
- 按正则关键词屏蔽垃圾消息（广告、链接、刷屏词），命中才拦截，不影响正常聊天
- 让个别用户跳过关键词屏蔽（白名单），但黑名单仍然最高优先级

## 规则优先级

消息进入插件处理阶段后，本插件按下面顺序判断，任一步命中即终止事件传播：

1. **黑名单命中** → 直接拦截（白名单无法豁免黑名单）
2. **白名单命中** → 放行，跳过后续正则判断
3. **正则命中** → 拦截
4. 都不命中 → 放行

## 工作原理

- 通过 `@filter.event_message_type(filter.EventMessageType.ALL, priority=999)` 注册高优先级事件监听器（AstrBot 中 `priority` 数值越大越先执行，默认为 `0`）
- 命中后调用 `event.stop_event()` 终止事件传播，同一事件的后续插件 handler、LLM 请求、结果装饰与发送阶段均不会执行
- 正则使用 `re.search` 对**消息纯文本**（`event.message_str`）匹配，一条消息只要命中任意一条规则即拦截；纯图片等无文本消息不参与关键词判断
- 每次事件都从配置读取规则，WebUI 修改后立即生效，无需重载插件；正则编译结果按规则集合缓存，配置未变时不会重复编译

> **限制说明**  
> NapCat 等协议端上报的底层原始日志（core.event_bus）依然会打印消息，这属于协议层行为，插件无法屏蔽，但**不会产生 Token 消耗**。  
> 白名单只豁免正则关键词，不能豁免黑名单。  
> 未被唤醒的消息（未 @、无唤醒前缀等）不会激活本插件 handler，因此也不会打印拦截日志；这类消息本来就不会进入后续处理。

## 配置项

WebUI → 插件 → QQ黑名单前置拦截 → 配置。三个配置项均为**列表**，可在面板中逐条增删，也支持批量导入（一行一个）。

| 配置项 | 类型 | 说明 |
| --- | --- | --- |
| `blacklist_qq` | 列表 | 黑名单 QQ 号，命中即全量拦截 |
| `whitelist_qq` | 列表 | 白名单 QQ 号，豁免正则关键词屏蔽；同时存在于黑名单时仍被拦截 |
| `keyword_regex` | 列表 | 屏蔽关键词正则，每项一条 Python 正则 |

配置示例（实际存储于 `data/config/astrbot_plugin_block_qq_config.json`）：

```json
{
  "blacklist_qq": ["111", "222"],
  "whitelist_qq": ["333"],
  "keyword_regex": ["广告", "https?://", "(?i)点击领取"]
}
```

正则说明：

- 使用 Python `re` 语法，默认区分大小写，可用 `(?i)` 前缀忽略大小写
- 单条正则非法时只会在日志中报错并跳过该条，其余规则继续生效
- 避免编写可能灾难性回溯的正则（如嵌套量词 `(a+)+`），否则大文本下可能拖慢事件循环

## 安装与使用

1. **插件市场安装（推荐）**：AstrBot WebUI → 插件 → 插件市场 → 搜索「QQ黑名单前置拦截」安装
2. **手动安装**：将 `astrbot_plugin_block_qq.zip` 压缩包放入 AstrBot 的 `data/plugins/` 目录下解压
3. 在 WebUI 插件配置中维护黑名单、白名单与正则列表，保存后立即生效

## 如何确认拦截生效

命中黑名单时控制台输出：

```text
【前置拦截】黑名单用户 111
```

命中关键词时控制台输出（含命中的正则）：

```text
【前置拦截】关键词命中 'https?://' 用户 111
```

出现上述日志 = 拦截成功，该消息不会进入后续任何插件和 LLM 处理。

## 环境要求

- AstrBot >= v3.4.21（`priority` 参数自该版本起支持；列表型配置需较新的 WebUI）
